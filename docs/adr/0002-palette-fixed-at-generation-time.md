# Color Palette is fixed at template-generation time, not runtime-switchable

We considered shipping the Generated App with an in-app palette switcher alongside the light/dark Theme toggle — the more common pattern for "pick your colors" UIs. We chose instead to make Palette a `--palette` parameter resolved once when `dotnet new blazorserver` runs, baked into the generated Tailwind CSS with no in-app UI to change it afterward. A template consumer is choosing their product's brand color, not offering visitors a cosmetic preference the way light/dark mode is — so it belongs at generation time, not runtime. This keeps the Generated App's CSS output smaller (only the chosen palette's variables ship) and avoids building contrast-safe switching UI for a choice that, in practice, is made once per product.
